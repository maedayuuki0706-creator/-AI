# 競艇AIナビ：複数ページ版（2026-10-19）

6つの主ページと独立URLを持つ静的サイト。公開前レビューは
[RELEASE_REVIEW.md](docs/RELEASE_REVIEW.md)、解析・SEO設定は
[ANALYTICS_SEO.md](docs/ANALYTICS_SEO.md)を参照。

ページを編集するときはbuild_pages.pyを更新し、python3 viewer/build_pages.pyで生成する。
ブラウザはassets/app.mjs・data.mjs・analytics.mjs・site.cssを利用する。
GitHub/Sheets/Discord/Xへの書込みを行わない。予想は明示ボタン後だけ取得する。
GA4は既定で無効。既存公開サイトへの反映はユーザー承認後のみ。

確認用の独立Sitesには、build_pages.pyのoutput・preview・origin引数で作った静的ファイルを配置する。
本番は従来のRender静的配信がそのまま利用でき、追加のサーバや有料依存は不要。
旧JS/CSSは既存CI互換のため保持しているが、現行HTMLからは読み込まない。

以下は以前の1ページ版の設計記録。現行版の仕様・制約は上記のレビューを優先する。

# 旧版：PT2 & 出走表 閲覧専用ビュー

このフォルダは、既存の競艇AI本番システムと独立した**公開静的サイト**です。

## 仕組み
- 競艇場、日付、R番号の選択はブラウザ内だけの状態。GoogleスプレッドシートのB2/C2/A3は更新しません。
- **PT2予想**: 公開GitHubの `data/prototype12_delivery/predictions/YYYYMMDD_JCD_RR.json` に書き出された保存済みモデル結果を閲覧します。現行の `strategy_cards.cards` から総合型・本命型・妙味型・高配当型を表示します。『激絞り』などSheet側の独自組み立て表示は含みません。
- **出走表**: 独立サービス `boat-sheet-feed.onrender.com` の読み取り専用CSV `venues.csv` / `race.csv` / `race_roster.csv` を参照。場とRごとに読みます。
- **選手検索**: `選手データ`シートの1660名の表示用スナップショットを検索時に読み込みます。名前の部分一致、空白を無視したフルネーム、全角/半角登録番号に対応。1〜6コース1着率、決まり手、平均ST、評価・コメントを表示します。空欄と0を区別します。
- 選手情報の更新は既存の `main/data/sheet_db/meta.json` を先に確認し、新しい場合のみ既存 `players.json` を取得します。Sheets認証や書き込み、予想生成、配信処理は呼び出しません。
- **高速表示**: `build_data.py`は取得済み予想・日和の公式出走入力から直近7日分の最小JSONを作ります。約92KBの予想は、6艇の出走情報を含め約2.4KBになります。新しいレースは既存mainブランチの公開データにフォールバックし、表示対象レースを検証します。
- 出走表は保存時点のデータを先に表示します。保存がない場合や「情報を更新」を押した場合は既存公式フィードを取得します。無料フィードの休止による待ち時間が出ることはあります。
- PT2更新は小さい既存配送記録のdigestを確認してから必要時だけ完全な予想JSONを取得します。強制更新時は直接取得します。表示・再取得は元の配信に干渉しません。
- CSS/JSを独立ファイルに分け、HTTPキャッシュと最大75件のレース用localStorageを使用します。選手データは検索時のみ取得し、次回表示はブラウザ保存データから開始します。
- 予想ソースには更新遅延があります。配信・スプレッドシートの現在値と常に完全同期しているとは限りません。見つからなければ空欄表示で、別レースを流用しません。
- GitHub rawのアクセスができないネットワークでは予想を表示できません。公式やソースへのリンクを案内します。
- このサイトは認証機能がありません。**公開されているデータだけ**が対象です。秘密キー、Webhook、個人データ、内部管理APIにアクセスしません。

## 公開方法
- Render Static Site / Root `viewer/` / Build Command `echo static-ready` / Publish `viewer`
- 専用featureブランチで新規サイトを作成すること。既存の `main` や `sheet-auto-update` のRender配信サービス設定を変更しないこと。
- アクセス権が必要になった場合は、別途認証付きのバックエンド設計に切り替える。
- 表示用データの再構築: リポジトリ直下で `python viewer/build_data.py`。出力の `viewer/data/races` と `manifest.json` をviewer専用ブランチに含めます。既存の配信・取得ブランチは変更しません。

## 動作確認
- 日本時間の現在日が既定になること
- 日付・開催場・Rを切り替えても元シートは変わらないこと
- 存在しないPT2 JSONが404の場合、別レースを表示せず案内すること
- 出走表が欠損していてもエラーの内容を示すこと
- スマホ幅で4つの戦略カードが縦並びになること


## 2026-10-18 締切順ビュー（公開未反映の研究差分）
- 固定既定値「若松8R」を廃止。URLで日時/場/Rを指定していないアクセスでは、JST基準でまだ締切前のレースを全開催場横断で選択する。
- 締切前一覧は締切時刻の昇順。締切と同時に自動除外し、未手動選択時のみ次のレースに切り替える。利用者が指定したレースを勝手に上書きしない。
- 20秒ごとに表示を更新し、約2分ごとに日程データを確認する。データ提供側は最大300秒キャッシュを使う。ブラウザが非表示のときは周期的な通信を控える。
- 第一ソースは main/data/race_cards/YYYYMMDD.json（当日一致・complete:true のみ）。欠測時には読み取り専用の /schedule.json?date=YYYYMMDD を呼ぶ。**予備データ元は独立サービス boat-ai-navi-schedule.onrender.com（freeプラン）です。既存の boat-sheet-feed は未変更。**
- 両方不在なら欠測表示と手動セレクターを残す。最後の取得に失敗しても前日・別レースの締切や予想を代入しない。
- 「全レース」とは、公式で当該日の開催・締切が確認できたレースのこと。事前未公開レース、欠測レースは表示済みと偽らない。
- 締切順の画面は公開済みの締切時刻に基づく。予想の生成・更新とは独立しており、予想原本が未生成なら「未公開」と表示する。全ての締切前レースに予想が存在する保証ではない。
- 自動更新のために既存のDiscord/X、予想生成、Sheets、既存ワークフロー、Secrets、Render環境設定を変更しない。
- フロントテスト（Node.js環境）: node viewer/tests/test_live_schedule.cjs。今後の公開前に実際のブラウザ、JST日付跨ぎ、Render経由の /schedule.json、1レース当たりの負荷とネットワーク失敗時を確認する。


## トップページ・モーターAI評価（ドラフト）
- ホームに「競艇AIナビ」の概要、次の締切（確認済み実データのみ）、無料予想・モーター評価・選手検索へのショートカットを追加。架空の実績や架空の時刻を表示しない。
- ホームのモーター収録数と更新日時は、公開済み main/data/sheet_db/meta.json から読み込む。取得できなければ欠測と表示。
- 選択レースの「モーターAI評価」タブで、1〜6号艇の各モーターを **場コード＋モーター番号** で main/data/sheet_db/motors.json と結合。選手・モーター番号が取れない場合は推測しない。
- 元のランクは競艇AI データベース「モーターデータ」に存在する総合／出足（launch）／行き足（run）／回り足（turn）／伸び足（stretch）の S・A・B・C・D。表示は S=◎、A=○、B=△、C=注意、D=低、欠測=—。新たな予想ロジックや未検証の実力評価ではない。
- 初期表示では約600KBのモータースナップショットを読み込まず、評価タブを開いた時にだけ読み込む。参照元と更新日時を表示し、過去開催日より新しい評価には事後データ混入注意を明示する。モーター交換日が選択日より後の場合は印を表示しない。
- 当該レースの直前展示・整備で評価は変化し得る。現在のデータベース評価を「締切前に固定された学習入力」と誤認させない。
- SEO用のタイトル・概要・OGメタデータを追加（アクセス数の増加を保証するものではない）。
- 試験: `node viewer/tests/test_motor_panel.cjs` と `node viewer/tests/test_live_schedule.cjs`。加えて、スマホ・日付跨ぎ・データ無し・モーター交換・API通信・実際の予想リンクを公開前に確認する。
- この差分は安全確認用の別ブランチのみ。現在のRender公開サイトに未反映。既存の X/Discord、本番予想、Secrets、既存Render設定は無変更。


## 予想の表示は「見たい人がクリック」のみ（2026-10-19研究変更）
- 初期トップページには買い目も予想タブも自動表示しない。ホームで「全国の締切順・モーター・選手情報」を探し、予想を見たい利用者が「予想を見る」を押した時だけPT2予想を取得して描画する。
- 具体的な入口はトップナビ「予想を見る」、ホーム機能タイル「AI予想を見る」、出走表「このレースの予想を見る」、詳細タブ「予想を見る」。クリックなしの予想取得はしない。
- 締切順一覧でレースを選んだ場合は「出走表」を開く。予想は開かず、レース切替でも予想データを引き継がない。
- 出走表の軽量スナップショットは viewer/data/cards/YYYYMMDD_JCD_RR.json に分離（build_data.pyで生成）。PT2予想を含む従来の viewer/data/races/*.json は、予想がクリックされたときだけ取得する。カードが未生成なら公開済み hiyori/requests → 既存公式フィードへフォールバック。
- 予想確認中にバックグラウンドで自動レースが切り替わらないよう、利用者が明示して開いたレースを固定する。締切順の「次のレースへ戻る」で再開可能。
- GA4が**ユーザー承認を得て正しく設定された場合のみ**、予想ボタンクリック時に `prediction_open` イベント（開催日/場コード/R/入口）を送れるフックを用意。現在の公開サイトにはGA4が導入されていないため、このPRだけではイベント集計は始まらない。
- 現状でも予想データはGitHubで公開されており、認証・有料制限のある非公開コンテンツに変換するものではない。
- 回帰試験：`node viewer/tests/test_prediction_opt_in.cjs`（ホーム初期表示/自動締切選択/ユーザークリック/選択変更/イベントフック）。新たな本番予想や配信処理の変更なし。
