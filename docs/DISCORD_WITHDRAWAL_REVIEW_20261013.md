# 鳴門8R 未送信の隔離調査

調査実行: https://github.com/maedayuuki0706-creator/-AI/actions/runs/38341778146

対象ログは送信139件・未送信1件・catch_up9件でdegraded、終了コード1。
公式結果の着順表は3号艇を「欠」と記載する。保存した展示情報は5艇。
既存の `prototype3_delivery.build_record` は展示6艇を必須とする。
予想・確認IDがないまま締切を過ぎ、watchdogが同じ未送信を検出し続ける。

ただし、結果は事後情報である。締切前に欠場を検出して意図的に見送った
ことは証明できない。欠場と未送信の関連を記録しても、未送信を解消した
とは扱わない。明示的な欠場のない展示5艇や取得失敗は対象外。

このPRは独立した読み取り専用の分類関数・証拠・テストだけを追加する。
dispatcher、watchdog、予想計算、送信ガード、既存ワークフローを変更せず、
本番から関数を呼び出さない。入力をコピーして診断欄を追加するだけで、
status、counts、active_missed、送信確認ID、原本記録は保持する。
HTTP送信・状態ファイル書き込み・通知・締切後再送の機能を持たない。

今後の候補: 独立した運用表示に確認済み欠場の注記を出す。健康判定から
除外するには、欠場時の配信方針と締切前の証拠を別途検証する必要がある。
5艇レースの予想対応は予想計算に関わるため別作業。
