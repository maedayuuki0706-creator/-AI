# 万舟シャドー警戒 → 穴くんスナイパー融合構想（2026-10-10）

## 原則

**現時点は調査用データ収集のみ**。既存の穴くんスナイパーの `_is_selected_longshot`、予想ロジック、Discord・X配送ルートを改変しない。既存の `opportunity_alerts.py` は専用のスナイパー判定を備え、予想点数・EV・攻め圧等で発報を制限している。研究側を先に確かめる。

## Phase 0: 10/10 からの内部学習事例収集

- `manshu_shadow_watch.py` が締切前・未確定の6艇展示をスナップショットとして凍結し、イン敗北警戒／ヒモ荒れ警戒／非警戒を分類。
- **非警戒で実際には万舟だったレース**は `learning_YYYYMMDD.json` の `missed_manshu_cases` に、事前条件・未発報ゲート・公式決着・配当を別のフィールドとして保存。
- アラート内万舟 `alert_manshu_cases` と **万舟が出なかった対照例** `non_manshu_control_cases` も全件保存。的中例のみからルールを作らない。
- 見逃しの1着艇・5/6絡み・波／風／ST／展示順位・ゲート未達理由を集計する。個別の事例を自動で「勝ちパターン」に昇格させない。
- 出力は専用ブランチ `research-manshu-watch-state` へ。配信システムへ通知・配信変更しない。

## Phase 1: スナイパーの予測ログとオフライン照合

共通レースID `YYYYMMDD_JCD_RR` で結合し、**締切前の情報だけ**をモデル入力とする。

- 研究側: 凍結した6艇展示・風速・波高・内凹み・外艇タイム優勢・発報理由。
- スナイパー側: 予想確率、各頭確率、スコア、選定ゲート、候補買い目、投票時のオッズ、各点EV、選定/非選定理由、取得時刻。
- 公式結果側: 3連単決着、100円当たり配当、1号艇頭か、3/5/6号艇の着順。
- **レース終了後しか分からない結果、本番ST・本番進入・確定気象**は学習ラベル・事後分析のみに使う。旧 `exhibition_log.py` は確定結果で風速/波高が上書きされるため、事前スナップショット未取得時の再構築は禁止。

## Phase 2: 4方式を同日同条件で比較

1. 既存スナイパー単独。
2. 万舟シャドー警戒単独（レース選別の実績のみ）。
3. 警戒 AND スナイパー選定。
4. 警戒 OR スナイパー選定、もしくは警戒スコアをスナイパーの特徴量に追加。

分析は**未来日をホールドアウト**し、ルール変更日をバージョン固定。取り逃した万舟のうち、既存スナイパーなら拾えたレースを必ず別集計する。過去日の結果を見て作ったルールを同じ日付で高精度として再評価しない。

## 成績の定義

- アラート発報率 = アラートした確定済みレース / 観測・確定済みレース。
- アラート万舟率（精度）= アラートしたレースのうち万舟だった件数 / アラートした確定済みレース。
- 万舟捕捉率（再現率）= アラートして万舟だった件数 / 観測・確定済みレース中の全万舟件数。
- 見逃し率 = 非アラート万舟件数 / 観測・確定済みレース中の全万舟件数。
- スナイパー実買い目の的中率・万舟的中率・回収率は **別々に** 算出。「万舟レースを見つけた」ことを「万舟の的中」と呼ばない。

仮目標: 警戒率20%以内、アラート内万舟率30%以上、万舟捕捉率30%以上。いずれも条件を動かさない別日の実測で検証する。**スナイパー買い目の万舟的中率30%を達成したとは言わない。**

## Phase 3: 配信機能の統合（将来、結果が良い場合だけ）

事前に安全確認と試験を行った上で、別設定により `shadow_only` → `shadow_compare` → `live_candidate` を移行。既存の万舟・穴チャンネルの配送を止めず、同レースの二重投稿を防ぐ。最初は内部ログ検証のみ、ユーザー合意なく実配信の選定条件を変えない。

## 監視と制限

- `source` はレース締切前の6艇展示があるケースに限る。見られなかったレースは「非アラート」と誤分類しない。
- 異常日・中止・返還・進入変更後の結果・未確定は別フラグとして判定・集計から除外または明示する。
- データ不足時は判定を保留。レース終了後の変化から過去のアラートを発生させない。

## 2026-10-10 追加：弱イン場では通常のイン敗北をアラートにしない

**『その場なら2・3号艇が勝つのは普通』と『異常な荒れ方が起きそう』を分離する。**

- 暫定の弱イン場フラグは**公式に直近3か月の1コース1着率50%未満と確認できた場**のみ。2026年7〜9月は戸田42.8%、平和島40.5%、江戸川48.8%。対象と出典は `manshu_venue_context.py` に保存。統計の期間と取得元も固定して振り返れるようにする。
- この3場では、単に**1号艇が展示下位、風が強い、2・3号艇にA1選手がいる**といった通常のイン敗北要因だけでは「イン敗北警戒」を発報しない。戸田で2・3号艇A1が頭になりそうなのは**通常の予想候補**であって、それだけでは『万舟になりそうな異変』ではない。
- 例外は、**2・3号艇にA1がいて、該当艇の展示ST・展示タイムが1号艇に明確に優勢**で、さらに悪化水面や複数の顕著な展示差がある場合。A1という肩書だけで警戒にしない。
- 「ヒモ荒れ警戒」は独立した別の条件として残す。弱イン場でも対象となりうるが、「イン敗北警戒」と混同しない。
- 抑制されたレースは消さずに `venue_context` と `baseline_in_loss_suppressed` を保存。もし万舟になれば**アラートなし万舟**として理由付きで研究データへ入れる。
- **これは2026-10-10 v2からの暫定判定**。公式の1コース勝率はコース別指標であり枠別データとは異なる。展示進入が1コース以外の例外は今後の研究対象。
- 未確認の場を勝手に「弱イン場」と認定しない。24場の公式近況を継続検証して更新する。**公式場別イン勝率が低いだけでは万舟警戒の十分条件ではない。**
- このゲートの閾値は確率校正済みではない。通常の万舟警戒AIと同じく後続日の実測で精度/捕捉率/空振り数を比較する。既存スナイパーの配信やロジックには触れない。
