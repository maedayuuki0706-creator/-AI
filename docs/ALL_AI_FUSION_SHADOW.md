# 全AI融合・新規ログ専用テスト

既存の予想を同じ当日スナップショットで計算し、新しい融合予想を10点・各100円で仮想評価する。通知と実際の購入は行わない。

## 保存先と運用

- コード: `main` の `fusion_shadow.py`、`fusion_shadow_runner.py`。
- 状態: **`research-fusion-shadow-state` ブランチ**の `data/fusion_shadow/`。
- 成績: `summary.md` と `summary.json`。日別集計もJSONに保存。
- 自動実行: `.github/workflows/all-ai-fusion-shadow.yml`、JST 08:03〜23:58の5分間隔予定。GitHub Actionsの遅延・欠測は `coverage/` に記録。
- 各レースの最初の有効な展示スナップショットを固定。締切5〜30分前に取得対象とし、計算完了時に最低3分の余裕を要求。
- 独立した実行グループ、85秒の収集予算、並列3レース。既存の配信コード、配信ワークフロー、Webhook、X認証情報は変更・使用しない。

このブランチはログ専用で、mainへのマージ対象ではない。初期ツリーに本番コードを含めない。研究ログをmainへ毎回コミットしない。

## 何を融合するか

| 入力・既存システム | 使い方 |
|---|---|
| 既存メイン・展示・進入・選手傾向・前日成績・水面/潮汐・既存bridge補正 | 既存確率20%と、元の買い目・メイン厳選・頭固定圧縮の保存 |
| PT2のGoogle Sheets DB | **DBで直接補正した120通りの確率を25%**。元のPT2カードの確率をDB確率と取り違えない |
| `prediction_engine_v2`の場/展開知識 | 同じ事前入力で計算した確率5%。相関のある既存系統内の重み |
| 実際の日和データと日和モデル | 確率50%。6艇の選手一致と実データ利用を必須にする |
| PT1嗅覚BOX・抑え・穴、PT2総合、本命/妙味/高配当、PT3ゆうき | 元の選定ロジックで再計算し候補合意に使う。元の点数も保存 |
| 中穴/穴の候補・厳選 | 候補と選別通過の両方を記録 |
| X用AI重なり・配当期待・統合チケット候補 | 純粋な候補関数だけ計算。投稿上限・投稿済み状態・投稿は呼ばない |
| 万舟研究の場別判定 | その場で取得した6艇・風・波・展示STから再判定。弱イン場の通常のイン負けを過大評価しない既存ゲートを使う |
| 市場構造・展開 | 元の各予想の入力と分析に含め、スナップショットで固定 |
| 旧 `fusion_prototype` | 元の読込口が `ready=False` 固定のため独立票にしない。利用不能の理由を保存し、実データの日和モデルを使う |
| `all_ai_learning`など結果分析 | 予想エンジンではなく振り返り。独立した票にしない。既存で適用されるbridge補正はそのまま保存 |

PT1/PT2/PT3と厳選カードは相関のある選定レイヤーなので、票数を単純に足さない。買い目ごとに「既存系」と「日和系」の合意を各1回まで、最大20%の順位補正に限定する。派生カードを何枚複製しても重みは増えない。

融合の本線6点を補正確率順位から選び、重複しない抑え4点を選ぶ。抑えのEV倍率は0.9〜1.1に制限し、事前の万舟警戒による追加補正は最大8%。データがない場合は未取得として保存し、警戒なしと区別する。

重み・買い目選定は **`all-ai-fusion-shadow-v1` の固定仮説**であり、確率校正や優位性の実証はまだない。成績を見て変更する場合は別バージョン・別検証期間として扱う。

## 後出し予想を除く

1. 当日・締切前・6艇の一致・展示の完全性を検証する。日和取得時刻と作成時刻の順序、DBの更新時刻が取得前であることを確認する。
2. 当該レースの着順・本番ST・本番進入・払戻情報は予想に入れない。過去のレース情報は各既存モデルの時点フィルターを維持する。
3. 予想と取得入力を一度だけ保存。再実行しても予想を上書きしない。入力ハッシュ、コードSHA、全モデルの買い目、点数、金額、採用理由、事前の風・波・潮汐を残す。
4. 予想ログをリモートにpushした**後**に保存確認時刻とコミットSHAを記録する。保存確認が締切後なら成績から除外する。
5. 締切3分後以降に公式の3連単払戻だけで採点する。予想を再計算しない。返還・中止・特払い・同着を扱い、結果が未取得なら未確定のままにする。

確率入力の一つでも不足すると融合予想を作らず、理由をcoverageに残す。欠測を外れや0円払戻として混入しない。単に過去のデータで新ルールを再計算しても事前予想の成績とは呼ばない。

## ログ構造

```text
data/fusion_shadow/
  predictions/YYYYMMDD/YYYYMMDD_JJ_RR.json   固定した融合・各比較カード
  snapshots/YYYYMMDD/YYYYMMDD_JJ_RR.json.gz 当時の全確率・日和取得データ
  checkpoints/YYYYMMDD/YYYYMMDD_JJ_RR.json  push後の保存確認
  results/YYYYMMDD/YYYYMMDD_JJ_RR.json      公式払戻と返還
  evaluations/YYYYMMDD/YYYYMMDD_JJ_RR.json  元の予想に対する採点
  coverage/YYYYMMDD/*.json                 欠測・時間不足・対象レース
  cards/YYYYMMDD.json                      公式締切予定
  heartbeat.json                          最新の運転状況
  summary.md / summary.json               集計
```

## 比較と検証

融合10点と4つの `control_*_10` は同じレース・同額1,000円で比較する。`native_*` は元の候補カードをその点数のまま100円ずつ買った場合の比較で、実際に配信された予想と同一とは主張しない。厳選が条件を満たさない場合は0点の見送りとして記録し、的中率の分母に入れない。

的中率、投資額、払戻額、回収率、万舟的中数、日別集計を記録する。万舟の「警戒が出たこと」と「買い目が的中したこと」は別で、警戒だけを的中として数えない。欠測は別途coverageで確認する。

ローカル/CI検証:

```bash
python -m unittest discover -s tests -p 'test_fusion_shadow.py' -v
```

通知関数・本番ログ書込・結果取得を呼ぶと失敗する統合テストに加え、時点違反、DB入力、相関票の重複、不可変保存、リモート確認、返還/中止/同着/特払い、未確定の除外を検証する。人工のテストデータは本番の成績ログには保存しない。
