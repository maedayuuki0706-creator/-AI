## 仕組み

共通の新ゆうき展開v2から6艇各頭の攻めの起点、勝ち筋、負け筋、2/3着の形成候補を作り、場別AIが研究用の加点減点と10点の仮想カードを作る。場別の予想と共通版を分けて比較し、決して本番に自動採用しない。1点100円均等の仮想評価のみ。

七項目:
1. コース適性：展示で実際に確認した進入コースと場別1着率。現行DBのコース率は期間・標本が明らかでない研究用暫定事前分布。選手の2連対率を1着率として流用しない。
2. モーター：公式2連対率と事前の級別・出足・伸び・回り足。2連対率から伸び足を断定しない。未来のDB更新を利用しない。
3. 風：風速・風向を記録。条件別コース補正は200R以上かつ期間外検証に通った場合のみ。現状の風向は公式直前パーサーで欠測する場合あり。
4. 潮位：海水・汽水かつ場に潮汐のある3場だけ。推定潮位は競走水面の実測潮流ではない。未検証の効果はゼロ。
5. 進入：枠と実際の進入を区別。コース率は進入位置に適用。進入変更の二重加点は禁止。
6. ST隊形：平均STの6艇相対差。展示STは観測LOGのみで直接加点しない。
7. 水面：波高を記録。うねりの方向・潮流を想像しない。条件別補正は期間外検証を必須とする。

## 保存・運用

研究専用ブランチ research-venue-specialists-state の data/venue_specialists_v1 以下に、inputs、forecasts、receipts、coverageを別々に保存する。

予想の入力と6艇の筋、得点の内訳、買い目を締切3分前までに固定し、上書き禁止。リモートpush後の一致照合と受領証が揃って初めて保存成功と呼ぶ。締切前予想が未生成・未保存のレースは欠測にする。結果を見てからの書き換え禁止。

現状では風・潮位・波高の検証済み補正テーブルが未用意なので、環境値は記録するが補正ゼロ。後からデータ取得・外部検証が通った場合だけ有効にする。数値は順位付け用の未校正研究スコアであり、勝率・EV・実投票の推奨ではない。

研究版が動いているかはGitHub Actionsの成功表示だけで判断しない。実際の予想原本件数、締切前保存時刻、receipts、取り逃がしたレースを突合する。今後は公式結果を別工程で照合し、予想の選択ミスと実際の展開読み違いを分けてLOG化する。

テストコマンド: python -m unittest discover -s research/venue_specialists_v1/tests -v

手動研究実行: python -m research.venue_specialists_v1.run --out data/venue_specialists_v1

**研究用のコードが追加されただけでは自動開始ではない。** 新しい独立GitHub Actionsが実際に起動し、締切前の原本・受領証が作られた場合にのみ17日から開始したと報告する。既存配信・本番予想・Secretsは変更しない。
