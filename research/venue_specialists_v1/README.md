## 仕組み

共通の新ゆうき展開v2から6艇各頭の攻めの起点、勝ち筋、負け筋、2/3着の形成候補を作り、場別AIが研究用の加点減点と10点の仮想カードを作る。場別の予想と共通版を分けて比較し、決して本番に自動採用しない。1点100円均等の仮想評価のみ。

七項目:
1. コース適性：展示で実際に確認した進入コースと場別1着率。現行DBのコース率は期間・標本が明らかでない研究用暫定事前分布。選手の2連対率を1着率として流用しない。
2. モーター：公式2連対率と事前の級別・出足・伸び・回り足。2連対率から伸び足を断定しない。未来のDB更新を利用しない。
3. 風：風速・風向を記録。条件別コース補正は200R以上かつ期間外検証に通った場合のみ。現状の風向は公式直前パーサーで欠測する場合あり。
4. 潮位：海水・汽水かつ場に潮汐のある3場だけ。推定潮位は競走水面の実測潮流ではない。未検証の効果はゼロ。
5. 進入：枠と実際の進入を区別。コース率は進入位置に適用。進入変更の二重加点は禁止。
6. ST隊形：平均STの6艇相対差。展示STは観測LOGのみで直接加点しない。
7. 水面：波高を記録。うねりの方向・潮流を想像しない。条件別補正は期間外検証を必須とする。

## 保存・運用

研究専用ブランチ research-venue-specialists-state の data/venue_specialists_v1 以下に、inputs、forecasts、receipts、coverageを別々に保存する。

予想の入力と6艇の筋、得点の内訳、買い目を締切3分前までに固定し、上書き禁止。リモートpush後の一致照合と受領証が揃って初めて保存成功と呼ぶ。締切前予想が未生成・未保存のレースは欠測にする。結果を見てからの書き換え禁止。

現状では風・潮位・波高の検証済み補正テーブルが未用意なので、環境値は記録するが補正ゼロ。後からデータ取得・外部検証が通った場合だけ有効にする。数値は順位付け用の未校正研究スコアであり、勝率・EV・実投票の推奨ではない。

研究版が動いているかはGitHub Actionsの成功表示だけで判断しない。実際の予想原本件数、締切前保存時刻、receipts、取り逃がしたレースを突合する。今後は公式結果を別工程で照合し、予想の選択ミスと実際の展開読み違いを分けてLOG化する。

テストコマンド: python -m unittest discover -s research/venue_specialists_v1/tests -v

手動研究実行: python -m research.venue_specialists_v1.run --out data/venue_specialists_v1

**研究用のコードが追加されただけでは自動開始ではない。** 新しい独立GitHub Actionsが実際に起動し、締切前の原本・受領証が作られた場合にのみ17日から開始したと報告する。既存配信・本番予想・Secretsは変更しない。

## 2026-10-17 復旧版 v1.1

**上記v1の暫定加点方針は停止しました。** 期間・標本の不明な場別コース率、モーター級別/2連対率、平均ST、展示タイムに対する追加係数は一切適用しません。DBと公式値は観測として保存します。検証済みの条件効果が実際に供給されない限り場別補正はゼロです。唐津は引き続き潮位入力・補正の対象外です。

10点は共通v2の戦術から候補を作り、観測で支持された分岐を先に各頭の候補を交互選択する固定の研究ポリシーです。仮説の重複回数を勝率や尤度と解釈しません。係数を追加せずに10点を固定できるようにしたもので、選択方針自体の優位性は未検証です。風・潮流等を使った検証済みの4場差が完成したとは報告しません。

### 原因と変更範囲

- workflowはactive、checkout参照は正しい研究ブランチ。最後のschedule実行は10/17 09:54 JSTで、13:33まで次の研究実行が作られていませんでした。競合・タイムアウトで止まったログはありません。GitHub内部でscheduleが省略/遅延した理由は外部から確定できません。
- 09:54のdue=0は最初の締切（児島10:51、江戸川11:14）の28分前より早いためで、それ自体は正常。その後の起動欠落を成功表示で検出できなかったのが運用上の問題です。
- 公式取得はこのセッションのローカル環境で両場12R分を取得できました。GitHub runnerでは8秒のread timeoutが両場で発生したため25秒に変更しています。空の時刻表を「対象ゼロ・エラーなし」にせず、開催なしが公式indexで確認できない限りエラーにします。
- 修理対象はresearch/venue_specialists_v1、独立workflow .github/workflows/four-venue-specialists-research.yml、状態ブランチresearch-venue-specialists-stateのみ。研究Pythonコードのmainへのマージはありません。既存配信/予想/取得/Secretsや他のActionsは変更しません。

### 自動運転

独立workflowは研究コードをcheckoutし、8分間の限定ワーカーで毎分試行します。各周期で「原本push→リモートSHAと入力/予想一致→受領証push→結果レビューpush」の順です。終了時に同じ研究workflowだけをworkflow_dispatchで継続し、毎時03/13/23/33/43/53分のscheduleを予備起動として残します。実行中ジョブは取り消しません。scheduleやdispatchもGitHub障害時の無停止を保証するものではなく、実レースの原本数・受領証・coverageで判断します。Actions権限の追加はこの独立workflowの自己継続用actions:writeだけで、新しいSecretsは不要です。

取得は純粋な研究用パーサーと25秒上限の公式GETに分離し、既存dispatchモジュールはimportしません。正しい6艇・展示進入・締切を確認し、解析完了が締切3分前を過ぎた場合は予想にしません。出走表と展示の生HTML、URL、SHA256、取得時刻を入力に保存します。公式結果の原文もresultsへ別保存します。中断して入力だけ残った場合、後から別入力で上書きせず欠測として扱います。保存失敗時のローカル証拠はActions artifactにも退避しますが、artifactだけの予想を締切前Git保存成功と数えません。

### 欠測・成績

- schedules: 全12Rの締切原本と開催一覧。未来の唐津/浜名湖は開始日前に対象化しません。
- attempts: 公開待ち・取得失敗と部分原本。結果を見た再生成は禁止。
- inputs / forecasts: 入力と6艇すべての勝ち筋・負け筋・攻撃起点・他艇反応・2/3着理由、固定10点とモデル版。上書き禁止。
- receipts: push先の同一SHAを確認し、Gitオブジェクトの入力・予想両方とダイジェストを照合。checked_atが締切前のものだけ成功扱い。
- coverage / summary/latest.json: 全対象数・ローカル原本数・保存成功数・締切3分前を過ぎた未確認数とID・今後の未確認数。公開待ちの試行失敗数と最終欠測数を区別します。
- results / reviews: 確定3連単・払戻・決まり手・6艇着順/実進入/本番STを別保存。返還等は通常成績から除外。10点100円で的中率/ROI/収支、本線先頭買い目の1着艇成功率、頭/2着/3着の選択ミスを集計。全6艇頭を買うポリシーなので「買い目のどこかに1着がある率」と先頭候補の成功率を混同しません。
- 共通v2レビューで支持された事前条件と実ST差、進入変化、決まり手と形成候補の整合を比較。結果だけから外れた各艇の実際の旋回や攻撃失敗原因を断定しません。映像による因果検証は未実施です。
