# 4場専門AI｜学習済みコース連動データを用いたV3選抜研究

状態：**独立研究・事後シミュレーションのみ。本番・Discord・X・サイトには未採用。**

## 解決したい問題

現行の場別専門V1は、共通scenario_v2で各艇の攻撃起点・勝ち筋・負け筋を仮説にしているが、未検証補正はすべて0。10点の配り方が固定の6頭均等に近く、2026/10/17〜19時点の通常採点68Rでは外れ59R中、44Rの的中出目が**共通の生成候補**になく、15Rが最終10点の選抜段階で落選した。専門AIごとの出走表、選手、風、潮、モーターの時系列外検証がまだなく、加点に利用してはいけない。

## 追加した研究の実体

- `selection_v3.py`：**各場の公式K原本の学習済み分布**（2026/06/30以前）から全120通りを順位付け。公式の3連単・決まり手×後続2艇の頻度を利用。予想時の当該レース決まり手、結果、ST、払戻は受け取らない。
- A：場ごとに学習した3連単頻度（Dirichlet平滑化）の順位上位10点。
- B：場ごとの決まり手を周辺化した後続2艇の条件付き分布の順位上位10点。既存Phase2 Bの「事前仮説支持による優先順位」は含まないので、名称は**B学習順位のみ**。
- V3：Bと同じ学習順位を使い、**同一1着を最多5点、同一1着→2着ペアを最多2点**として10点抽出。頭の均等6頭配分を義務付けず、強い1着を多めに残せる。
- 選手・モーター・展示・風・潮位などの**未検証係数は追加しない**。事前展開仮説と歴史データの位置づけを別項目に保存。
- 全120出目と採用10点・落選110点、場別学習モデルのdigest、締切前原本digest、全6艇勝ち筋・負け筋の仮説、モデルの情報入手可能時刻を保持。新しい研究LOGを本番予想や既存研究状態に混ぜない。

## 入力の時系列防壁

- 元の `data/research_four_venue_phase2/20251018_20261017/` の公式K監査済み履歴8,876レースを使用。現時点の学習モデルは2026/06/30以前の確定通常レースのみ（江戸川1,322、児島1,415、唐津1,309、浜名湖1,611）。
- 歴史比較は2026/07/01〜10/17で、現行V1の歴史事前原本がないためV1と比較しない。**Kの本番進入は予測への入力禁止**。レース前に進入の確定記録がなかったという理由から艇番=コースと事前仮定した参考比較のみで、実際の変更は結果分析専用。
- 10月19日は `research-venue-specialists-state` 固定SHA `75d7c047c801e57638f1ce824504e9ee4c571f0e` から**締切前にGitで受領・保存された入力だけ**をV3の入力に使用。結果の確認後に改良版を生成した「後付けシミュレーション」と明記。実配信済み予想扱いにしない。
- 既存の学習モデル生成・公開時刻が原入力の観測時刻を過ぎていたら停止する。**10月18日はモデルが22:15 JSTに完成したため、同日予想との後付け比較を実施しない。**
- 正常な非返還・判定確定レースだけで仮想1,000円を比較。返還、不成立、原本欠測は除外し、母数を明記。

## 検証方法

```bash
python -m unittest research.four_venue_phase2.tests.test_selection_v3 -v
python -m research.four_venue_phase2.evaluate_selection_v3 \
  --history data/research_four_venue_phase2/20251018_20261017/studies/eed2cf3775203abb/audited_races.json.gz \
  --models research/four_venue_phase2/model_manifests \
  --state /path/to/pinned/data/venue_specialists_v1 \
  --state-sha 75d7c047c801e57638f1ce824504e9ee4c571f0e \
  --out /tmp/four-venue-v3
```

- 研究ブランチでのpush時にだけ `.github/workflows/venue-selection-v3-offline.yml` でCIが実行される。**定期実行・自動生成・Discord配信・X投稿・Sheets書き込み・Secrets・Render・本番ワークフロー変更なし**。
- CIは2系統のread-onlyチェックアウト（研究コード、固定元LOG）を使い、GitHub Actions artifactに `summary.json`, `report.md`, `per_race.json` を置く。全解析は通信不要、Python標準ライブラリだけで再現できる。

## 意図的に未達として残すもの

1. 2026/10/20以降の**まったく新しい実開催での並行受領・100R/300Rの実測**は未実施。
2. 実際の進入、本番ST、1M、2・3着連動の映像学習は未実施。単なる的中出目から戦術理由を確定できない。
3. 風向欠測・潮位観測点／時刻整合・モーター使用期間・選手差の交絡は未検証。学習係数を勝手に導入しない。
4. 歴史比較の検証/最終期間は別研究者がすでに集計を見ており、**完全な未観測ホールドアウトではない**。多重比較から改善を断定しない。
5. アルゴリズム選抜の再調整は評価群を見て行わない。悪かった結果も残し、次の全く新しい日付で判断する。
