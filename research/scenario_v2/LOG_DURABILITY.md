# 新ゆうき研究 v2：LOG欠落防止の受入条件

## 現状と範囲

2026-10-16の調査時点では、新ゆうき研究シートの登録は10/14まで。
研究用のfusion_shadowは10/15にbudget_exceeded、10/16にnot_captured_before_window_closedがあり、締切前保存が成立していない。これはシートの行数不足ではなく、主に元の研究予想生成・保存経路の問題。

この追加コードは本番配信とは独立した**研究v2の軽量原本生成部品**であり、スケジューラ、GitHubへの保存、Sheets転記は**まだ接続していない**。
**現状、このコードを置いただけで明日から自動保存されるわけではない。**

## 必ず守ること

1. 締切前の事実だけを使用する。公式出走表と直前情報（6艇の展示タイム・進入）を取得し、レース日・時刻を記録。
2. 生成時点で3分以上の余裕がなければ「事前予想」は作らない。結果から後付けで予想を作らない。
3. inputs/<日付>/<レースID>.json と forecasts/<日付>/<レースID>.json を一度だけ書く。原本が変わったら上書き拒否。
4. 出力は最初 prospective_uncheckpointed。実際にGitHubへコミット・pushできたことをSHAとファイル内容で照合するまでは「保存成功」としない。
5. GitHubコミットが締切後なら、その原本を研究資料として残しても**事前固定実績の母数から除外**する。
6. GitHub原本を優先し、Sheetsは検索用の第二コピーとする。Sheets転記が失敗しても原本は保持し、再試行する。重複入力は日付・場・R・版・SHAで拒否。
7. 取得失敗、遅延、未処理、結果未確定、原本不一致を欠測として別途保存。予想の外れには数えない。
8. 投票、Discord、X、本番予想ロジック、Secrets、既存Actionの修正はしない。

## 実装済み（このブランチのみ）

- collector.py：公式出走表と6艇の展示情報による軽量な研究v2生成と不変保存。オッズや日和取得など時間のかかる既存融合処理に依存しない。
- verify_remote_receipt：別工程でGitHub push済みのコミット内容・締切時刻を照合して保存確認。
- tests/test_collector.py：早着・遅着、原本の重複・改変、remote照合の単体テスト（**実行結果は未確認**）。

ローカルでの手動起動例（レース当日、締切前だけ）：

    python -m unittest discover -s research/scenario_v2/tests -v
    python -m research.scenario_v2.collector --day 20261017 --jcd 06 --rno 7 --deadline 19:00 --out /tmp/yuuki_v2_log

実行例の日付・時刻・レースは架空。手動実行だけではリモート永続保存は完了しない。
