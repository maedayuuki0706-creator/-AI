# 究極超完全型AI予想｜ULTIMATE BOAT LAB 研究フェーズ

ユーザーが指定した BOATERS・ボートフロンティア・ボートレース日和、さらに独自データ分析AIを統合する研究計画。実装は機能・分析の**発想**を参考にし、公式出走表と競走成績、自身の観測ログから独立して再計算する。第三者の予想・コード・有料機能・ログイン後データを許諾なく収集・再配布しない。

## それぞれの研究テーマ

| コンセプト | 研究する因果・条件 | 独立実装の入力候補 |
|---|---|---|
| BOATERS型 | 枠別・場別の相性、1着艇を固定したときの2・3着連動、進入変更した場合の比較 | 24場ログ、選手×場成績、過去の三連単着順 |
| ボートフロンティア型 | 選手のコース別決まり手・実戦ST、内側と外側の攻防、1コース逃げ失敗後の他艇分布 | 公式の枠/本番進入/着順/ST/決まり手 |
| ボートレース日和型 | 外艇の展示差0.07〜0.10秒、前づけ・進入変更、チルト、ST差と1M展開 | 公式展示・スタート展示、独自展示、過去の実戦との差 |
| 独立分析AI | モーター期・使用履歴、当地成績、風・波・潮、オリジナル展示、オッズ変動、欠測・鮮度 | 個別時刻付きの公式・独立研究スナップショット |

参考元: 
- https://boaters-boatrace.com/guide/data-how-to-read
- https://boatfrontier.jp/racer/4003/course
- https://kyoteibiyori.com/ および /data/、/vup/

*「自分のAI日和」とウェブサイトの「ボートレース日和」は別の入力系統*。独自AI日和の確率を、同名だからとサイトの情報と混同してはならない。

## 目標の予測パイプライン

1. **受領原本**: YYYYMMDD・場01-24・R01-12・登録番号・枠番・展示進入コース。番組表、展示、オリ展、風波潮・モーター、オッズを個別取得時刻/公開時刻/出典とともに記録。枠と実進入を混同しない。
2. **ファクトチェック**: 6艇のID一致、モーター周期、場別タイム区間の違い、締切3分前ゲート、欠測はnull。過去結果は当日の予測入力へ入れない。
3. **場別・選手別モデル**: 24場モデルが直近データ（過去日のみ）で艇ごとの逃げ・差し・まくり・捲り差し・逃し、ST、コース別結果を統計。標本不足は階層的に共通データへ縮約するが、有効性を時系列外部検証で確かめる。
4. **6艇展開シミュレーション**: ①本番進入 ②ST先行/遅れ ③攻め起点 ④1M決着（逃げ/差し/まくり/まくり差し）⑤1着に条件づけた2・3着追走をつなぐ。相互に矛盾するコース配置は除外。単純な1着×2着×3着の独立積ではない。
5. **120通りの3連単確率**: 1Mシナリオの重みを未来未学習データで校正し、120通り総和1、枠別/場別の校正誤差・対数損失を監査。モデル性能が不足する場合は点数やEVを生成しない。
6. **市場モデル**: 同じ時点の公式3連単オッズで EV = AI予測確率×オッズ、点数・資金の制約を適用。連動による相関と市場控除率を考慮し、規則に合わない・不確かなレースは見送り。
7. **記録と学習**: 締切前の入力・予想SHA256を保存、リモート受領を証明。確定結果は別ファイル。的中率・回収率・校正誤差を日/場/条件別に集計。前向き比較で既存のメイン/日和/ゆうき/4場/24場の純増価値を測る。

## V0.1で本当に実装した範囲

research/ultimate_fusion_v1/engine.py は、標準ライブラリだけの独立研究エンジン。

- 公式展示に対応する6艇ID・本番結果混入・締切前の鮮度を検証。
- 24場対象の過去日三連単着順から、**1着艇固定時の2・3着頻度**を場ごとに集計（小標本は不明とする）。
- 内側に対して展示タイムが0.07秒以上速い外艇、進入変化、+0.5以上チルトを**研究仮説**として記録。
- 本番ST・結果・その日以降の結果を研究入力に混入させない。過去レースの集計と現在レースの予測を分離。
- 自動推奨・配信・発券なし、120通りの確率やEVは**校正済みモデルが無い限り生成しない**。
- 第三者サイトへHTTP接続しない。既存Hiyoriアダプターが実データを解析できていないという問題を隠さない。
- サイトのAI確率を勝手に既知の値として混ぜない。

単体テスト:
    python -m unittest research.ultimate_fusion_v1.test_engine -v

この段階の「融合」はデータの扱い方・個別指標・展開研究の一体設計であり、サイト三社のデータ直結や最終的な「高精度予想の完成」を意味しない。

## Phase 1: まず全24場の独自展示を安定保管

PR #55 と research-venue24-state-20261101 の保存ログを参照。3,901R、うち独自展示は一次原本25R・二次アーカイブ3,692R。二次アーカイブにはそのAI自身のレース前取得証明がないので、前向き精度の評価に使う前に、別の独立収集ジョブで実測・公開時刻・登録番号・モーターを固定し、欠測を明示する。

## Phase 2: 予測モデル実験

- 1頭が逃げた場合の2-3着連動、1頭が逃げなかった場合の勝った艇・1の残り方を対にして学習。
- 具体例: 4に伸びとSTの優位 → 3が握りにくい → 5の差し場 / 1の残りを検証。
- 進入別ST/枠/コース/決まり手/当地/モーター/風・潮の交互作用を条件付き統計と機械学習で比較。
- 6艇シナリオの統一確率と120通りの着順を予測。的中率だけでなく市場の期待値・回収率が基準モデルを上回るか見る。

## Phase 3: 実戦前向きテストと私有サイト

- 連続30〜90日（十分な件数を確認）、締切3分以上前の予測記録のみ評価。
- 本線・中穴・万舟の3グループ。見送りも損失回避の重要な選択として記録。
- 場別のROIと検証件数、欠測割合、配信漏れ、オッズ固定時刻、キャリブレーションの結果を表示。
- iPhoneの航跡 BOAT LABに「勝ち筋/負け筋」「6艇展開」「1着→2/3着条件付き確率」「オリ展」「EV」を見える化。本番は検証済みの版だけを別承認で採用。

## 最重要の安全境界

- main、Discord/X予想配信、本番予想、既存4場・24場研究、Cloudflare、Render、Secrets を変更しない。
- 独立ブランチのみ。研究CIには秘密情報・書き込み権限・cronを与えない。
- AIを多数混ぜるだけでは精度は向上しない。同一公式結果から生まれた特徴は相関が強く、過学習を防ぐため厳格な未来データ検証が必須。
- 現行の研究原本には結果が追記されたファイルがあるので、live分析ではそのまま読まず厳密に遮断。
- 現時点の研究指数は確率ではない。未校正スコアからオッズを掛けてEVを作らない。
