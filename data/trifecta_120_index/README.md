## データ仕様

- JSONデータ `races[]` は各レースのモデル名、元の保存済み予想のblob SHAと原本digest、生成・締切日時、120出目の順位と構造指数を含む。
- `columns` / `rank_columns` は120行配列の各列名（ファイルによって表記揺れがあるが並びは同じ）。順に `rank`, `combination`, `relative_index_0_100`, `heuristic_strength`, `max_support`, `hypothesis_count`, `tie_start`, `tie_count`, `hypothesis_ids`。
- 指数0〜100は同一レース内の未校正の展開根拠相対尺度であり、的中確率・公正オッズ・EVではない。スコアが並ぶ場合のrankは出目文字列順による便宜的な通し番号で、予測上の差を意味しない。
- 既存の展開モデルが候補として挙げるのは1レース **40/120通り**。残る **80/120通りは展開根拠なし・同点**であり、71位と100位などの順序を予測力と解釈しないこと。
- `support_max=0` の出目も根拠なしとは限らない（候補だが観測支持0のことがある）。展開候補かどうかは `hypothesis_count > 0` で判定する。
- 新ゆうきの部分展開は `virtual_card=null` の原本が対象で、完成した新ゆうきの最終的な買い目順位ではない。通常的中率と合算しない。
- 研究指数の生成は元の凍結予想より後。`prospective_index_verified=false` として保存し、締切前に生成していたという虚偽の扱いをしない。
